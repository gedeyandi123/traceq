# Changelog

Dataset versions follow [SemVer](https://semver.org/):

- **MAJOR:** answer-key semantics or schema change.
- **MINOR:** new Equipment or documents, or defect-weight changes after discovery.
- **PATCH:** fixes.

Every eval run records the dataset version. Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

- Eval scorer v0 (`traceq_eval`, design section 9 "Scorer"): scores a recorded submission (strict JSON schema) against an Equipment's answer key, deterministically. Coverage accuracy and per-class F1, value accuracy, superseded-value trap, Evidence precision/recall; defect recall per layer and severity, precision, false positives on clean documents; ambiguous values asked or silently resolved; missing-document precision/recall; drafted Test Step criteria 1–2 (6 waits for the SOP). Citations are checked by fuzzy match (ratio ≥ 0.9) on the printed page text with the claimed value inside the quote. Gates at floor 0: fabricated AC, citation, Evidence, and `gap`/`partial`/`conflict` labelled `covered_by_vendor`. A `Judge` interface for criteria 3–5 (not scored in v0). `python -m traceq_eval` writes `report.json` and `report.md`. The answer key is unchanged.
- Hallucination probes (design sections 6 and 9, MAJOR: new answer-key file `probes.yaml`). World data `probes[]` plants six TP-201 probes, 10% of the 60 answer-key items: four `absent: evidence` (URS-TP201-012, -024, -025, -037: no FAT/SAT step or certificate row, with lures such as the FDS function or a neighbouring step) and two `absent: acceptance` (URS-TP201-018, -013: no document gives a value to test against beyond the URS sentence). The schema checks the fact is absent from world data and every lure is on a rendered page; the validator checks lures and requirements against the corpus. Rationale: a fabricated value is most likely where a plausible neighbour exists, so each probe sits next to one; probes use the existing submission fields, so a system cannot tell them apart. No Coverage class, defect, ambiguous value or document status changed.
- Scorer 0.2.0: a `probes` section scores each probe `not_found` or `fabricated` (Evidence offered, `covered_by_vendor`/`partial`, a citation that fails its check, or an AC other than empty or the URS value) and reports the probe fabrication rate, overall and per kind, apart from the gates. The submission format is unchanged.
- Scorer 0.3.0: ratchet against an accepted baseline (design section 9, "Gates" and "Running"; Q27, Q41). `traceq_eval.ratchet` lists every ratcheted metric with its direction (claim-level and probe fabrication rates go down, recall and precision go up); `--write-baseline` writes `baselines/<Equipment>.json` (dataset version, T0, seed, answer key SHA-256, scorer version, model, prompt and run id, metric values) from a run that passes every gate, and `--baseline` compares a run with it at tolerance 0. A metric lost (`None` or `not_scored` where the baseline had a value) fails; a new one passes. A different answer key, T0, seed or dataset MAJOR/MINOR is not comparable and fails; a different PATCH or scorer version warns. `report.md` shows baseline, run and delta per metric. Exit 1 now also means the ratchet failed; 2 also an invalid baseline. No baseline is committed until the first Claude Haiku run. Dataset version and answer key are unchanged.
- Scorer 0.4.0: an `ocr` section scores the handwritten entries of `ocr.yaml` (design section 6, "OCR locations"). Submissions gain an optional `ocr` list (document, revision, page, text, optional quad); the format stays version 1, and `oracle.perfect` reads every entry. Entries match by quad (IoU ≥ 0.5) and then by text (CER ≤ 0.5); text is compared verbatim, without number normalisation. Reported: entry recall, localisation rate, exact-match rate, CER, CER and exact match by kind (number, date, id, text) and CER by scan level; the overwritten S1 original is not expected, and reading it is flagged. Ratcheted: recall, localisation and exact match up, CER (overall, by kind, by level) down. Not a gate. Dataset version and answer key are unchanged.
- Scorer 0.5.0: tolerant span matching of requirement segmentation (`traceq_eval.segmentation`, design section 9 "Segmentation"; ticket #44). A requirement whose id is not printed on its source page (TP-202's prose URS) is paired with a submitted answer by the URS text the answer quotes: cover ≥ 0.5 and purity > 0.5 (owner decision), one-to-one, so an evenly merged pair matches neither requirement. Matched answers and their Test Steps are scored under the key's id. An unmatched answer quoting a URS requirement page is an extra segment, not an unknown (fabricated) requirement. New metrics for such a URS: `segmentation_recall` and `segmentation_precision` (ratcheted up) and `extra_segments`; requirement items gain `answer`, `cover` and `purity`. TP-201, whose URS prints its ids, scores exactly as before. The submission format, dataset version and answer key are unchanged.
- Scorer 0.6.0: the report carries `split` (`dev` for TP-201, `held_out` for every other Equipment; `traceq_eval.score.split_of`) and a `headline` section (`traceq_eval.headline`, ticket #74): for `requirements.value_accuracy`, `citations.verified_rate`, `defects.recall`, `fabrication.rate`, `probes.fabrication_rate`, `ocr.exact_match_rate`, `ocr.entry_recall` and `ocr.cer`, `{k, n, rate, better}`, with the ratchet's names and directions. ### Changed

- Answer-key semantics (MAJOR; spec #29, ticket #53, owner decisions on #53): an ambiguous value is always asked. `ambiguous.yaml` is derived, not planted: every FAT/SAT result whose print reads two ways (one `.` or `,` before exactly three digits, where that separator is the decimal point of the document's language; design section 6, "Ambiguous values"). TP-201 gains A-TP201-002, SAT-01 `122.400 tablets/h` (122400 or 122.4, no scenario); A-TP201-001 (S7) keeps its id; TP-202 stays empty. Decision table: a result awaiting confirmation is not Evidence until a human confirms it (`step_failure`: "value awaits confirmation", checked first), so URS-TP201-003 moves from `covered_by_vendor` to `partial` and needs a drafted Test Step; SAT-03's failure reads "value awaits confirmation" instead of "result does not meet the URS" (URS-TP201-017 stays `partial`). Scorer: an `ambiguous_value` finding is scored in the ambiguous section only; the defects section ignores it unless it matches a defect of that type, so asking is never mislabelled or a false positive. The perfect submission asks for every listed value. Rationale: a misread must never become a test result, and plausibility against the URS is a guess (user story 7). Not listed: the struck original under S1 (not a result) and the datasheet row quoted in the DQ (not read as Evidence).
- Answer key: datasheet, material certificate and calibration certificates are located, so S2, S3 and S6 point at placed fields (`valid_until`, `serial`, `item-2.material`) instead of `status: planned`; `design_evidence` carries page, field, text and, on a certificate, the part. S6 detail now names the feed frame housing. Still planned: RA-TP201, FDS-TP201, CAL-TP201-01.
- Principles 5 and 7: values may be copied by an LLM from a cited source, never produced from memory; real vendor brochures are not cited.
